# PromptDock：从 AI 创作痛点到浏览器工具

## 项目定位

PromptDock 是一个围绕「提示词积累与复用」设计的个人产品项目。它面向需要反复使用角色、场景、构图与光线模板的 AI 创作者，也适合一般文字模板管理。

作者负责需求定义、信息架构、视觉与交互设计、体验反馈和版本迭代，使用 AI 辅助编码、调试及文档整理。技术实现是原生 HTML、CSS、JavaScript 和 Manifest V3 浏览器扩展。

## 从哪里发现问题

创作时，同一套提示词结构往往需要多次替换主体、场景和光线。聊天记录容易被新内容淹没，文档需要切换窗口，直接修改原文又容易破坏可复用模板。因此，将流程收敛为：**保存模板 → 检索模板 → 填写变量 → 复制使用**。

这是一项基于作者自身工作流和迭代反馈的产品探索，没有进行大样本用户研究，也没有可公开验证的效率提升百分比。

## 关键设计决策

| 观察／约束 | 产品决策 | 对应实现 |
| --- | --- | --- |
| 模板经常只改少量内容 | 用 `{{变量}}` 分离固定结构与临时输入 | 去重变量名、预览结果、复制而不改写原文 |
| 创作平台通常就在浏览器中 | 提供侧边栏、小窗和右键摘录 | 后台统一协调入口与窗口复用 |
| 个人内容不需要默认上传 | 使用本地存储，移除 AI API 功能 | 无账号、域名权限、分析统计；CSP 禁用网络连接 |
| 多窗口会同时修改同一条提示词 | 对数据变更进行合并与冲突检测 | 区分收藏等可合并操作与正文编辑冲突 |
| 默认内容过多会干扰用户整理 | 只保留一条示例与一个默认分类 | 自定义分类及 JSON 导入／导出 |
| 不同语言、不同使用环境 | 中英双语与明暗主题 | 偏好持久保存，切换时保留未保存草稿 |

## 信息架构与交互

主要入口是全部提示词、收藏、最近使用、分类和搜索；卡片提供查看、编辑、变量填写与复制。模板使用和模板编辑保持独立，让一次性的变量输入不会破坏积累下来的模板。

小窗与侧边栏切换时考虑未保存内容，重复点击图标复用已有窗口。置顶使用浏览器提供的 Document Picture-in-Picture，将原界面移动到浮窗，关闭后恢复，避免创建两套相互覆盖的数据和草稿。

## 可运行成果与验证

- 1.4.1 扩展源码和中英本地化资源。
- 新建、搜索、分类、变量复用、收藏和备份等完整本地操作流程。
- 66 项自动化测试在 2026-10-17 通过，覆盖数据、交互逻辑和模拟浏览器 API。
- 本次公开整理保持扩展代码与已有商店提交包一致。

自动化测试不能替代浏览器实测。置顶和侧边栏的实际支持受浏览器版本及策略影响。截图为同系列网页工作台的演示数据，不代表实际用户使用统计。

## 已知限制与后续方向

当前只提供本地保存，没有账号或云端同步，也不直接生成 AI 内容。卸载和清除存储需要提前备份。导入文件和模板规模较大时，需要进一步验证性能与交互。后续迭代可以围绕更清晰的变量说明、批量整理、无障碍和真实使用反馈展开。
